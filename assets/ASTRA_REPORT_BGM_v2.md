제작일: 2026-10-02. 기준: `BGM_REQUEST_v2.md`.

## 차분하게 바꾼 방식

- 사인파와 적은 수의 약한 배음으로 음색을 만들었습니다. 사각파·톱니파·노이즈 드럼·빠른 아르페지오는 사용하지 않았으며, 타악기도 넣지 않았습니다.
- C장조를 기본으로 전투는 D장조, 보스는 G장조입니다. I·IV·V·vi 화음을 두 마디씩 유지하고, 선율은 한 마디에 1~2음으로 구성했습니다. 8마디 단위로 선율을 조금 변주하고 숨 쉴 공간을 두었습니다.
- 타이틀은 둥근 오르골 어택과 낮춘 음역으로 설렘을 표현했습니다. 지도는 마림바의 짧고 부드러운 울림, 전투는 느린 전자피아노 문답, 보스는 낮은 선율과 긴 어택의 패드로 구분했습니다.
- 여관은 느린 속도와 드문 선율로 편안함을, 엔딩은 부드러운 호른풍 화음과 으뜸화음 종지로 축하를 표현했습니다. 엔딩은 마지막 한 마디 동안 서서히 작아집니다.
- 2.2kHz에서 약 −3dB가 되는 완만한 저역통과 처리를 적용했습니다. 오르골 선율도 MIDI 69~79 범위로 제한했습니다.
- 반복곡은 끝의 음과 잔향을 시작 부분에 감아 연결했습니다. MP3 인코딩 경계의 오차를 줄이기 위해 마디 경계 전후 50ms 안에서 진폭과 기울기가 작은 시작점을 선택했습니다. 반복을 위해 곡 전체를 페이드아웃하지 않았습니다.

## 검사 결과

생성 스크립트의 검사에 더해, 별도 `check_bgm_v2.py`로 최종 파일을 다시 읽고 ffmpeg의 EBU R128/true-peak 검사를 수행했습니다.

- **6/6곡 디코딩 성공**, 44.1kHz·MP3·60~90초 확인. 원본 합성 버퍼와 디코딩된 샘플 수가 일치합니다.
- 피크 **−6.001~−5.999dBFS**, 오버샘플링 true peak는 전곡 **−6.0dBFS**입니다. 클리핑은 없습니다. 기존 효과음의 약 −3dBFS 피크보다 약 3dB 낮습니다.
- 통합 음량은 **−18.9~−17.8 LUFS**, 곡 안의 음량 범위(LRA)는 **1.6~2.3 LU**입니다. 곡 사이의 통합 음량 차이는 1.1 LU입니다.
- 최종 신호의 2.5kHz 이상 에너지 비율은 모든 곡에서 **0.001% 미만**입니다. 에너지 비율은 FFT 분석치이며 청취 평가를 대신하는 지표는 아닙니다.
- 반복곡 5곡의 마지막·첫 샘플 차이는 **0.0000101~0.0001480**, 약 **−99.9~−76.6dBFS**입니다. 반복 경계 전후 100ms의 RMS는 곡 전체 RMS의 **0.77~1.15배**로, 경계에서 음량이 사라지는 현상이 없습니다.
- 반복곡에는 RMS가 −60dBFS 미만인 **10ms 무음 블록이 0개**입니다. 엔딩에는 의도적인 마무리 페이드에 따른 무음 블록이 있으며 마지막 샘플은 약 −156dBFS입니다.
- 효과음 24개, `index.html`, `src/` 파일들, `bgm_old/` 6곡을 포함한 **37개 보존 대상 파일의 작업 전후 SHA-256이 모두 일치**합니다.
- `audio_validation.json`의 BGM 항목과 `manifest.json`을 새 결과로 갱신했습니다. `finalize.py`의 BGM 검사 조건도 −6dBFS·60~90초로 갱신하여 전체 자산 검사를 통과했습니다. 기존 SFX 검사 기록은 유지했습니다.

## 검사 범위와 한계

이번 검사는 작곡·합성 설정 검토, 최종 MP3 디코딩, 주파수·음량·경계 파형 분석입니다. **직접 청취 평가와 실제 브라우저에서의 게임 재생 검사는 수행하지 않았습니다.** 따라서 주관적인 편안함이나 모든 재생 환경에서의 무결점 루프를 확인했다고 주장하지 않습니다.

게임 코드에서 Web Audio 버퍼를 반복하는 구조를 읽어 확인했으며 수정하지 않았습니다. MP3에는 Xing/gapless 정보를 기록했습니다. 자동 검사에서 인코더 지연 제거 후의 길이와 경계를 확인했지만, 재생기의 MP3 디코딩 동작은 별도입니다.

음악 생성 도구 탐색 시 Pinokio 제어 서버에 연결되지 않아, 요청서가 허용한 로컬 Python 합성 방식으로 완성했습니다. 외부 음원이나 상용 곡 샘플을 사용하지 않았습니다.

## 산출물과 재검사

- 제작: [tools/build_bgm_v2.py](tools/build_bgm_v2.py)
- 독립 재검사: [tools/check_bgm_v2.py](tools/check_bgm_v2.py)
- 곡별 상세 측정: [bgm_validation_v2.json](bgm_validation_v2.json)
- 독립 검사 결과: [qa/bgm_v2/independent_check.json](qa/bgm_v2/independent_check.json)
- 보존 확인: [qa/bgm_v2/protected_check.json](qa/bgm_v2/protected_check.json)
- `qa/bgm_v2/*_score.json`: 곡별 설정·선율·시작 시각 기록.
- `qa/bgm_v2/*_boundary.wav`: 끝 3초와 처음 3초를 이어 붙인 반복 경계 확인용 파일. 엔딩은 마지막 12초입니다. 반복곡 파일은 두 번 이어 놓았으므로 실제 경계는 3초와 9초 지점입니다. 6초 지점은 검사 구간을 다시 시작하는 편집점입니다.
- `qa/bgm_v2/*_loudness.txt`: ffmpeg 음량 검사 원문.

프로젝트 루트에서 다음 명령으로 현재 최종본을 다시 검사할 수 있습니다.

```sh
.venv/bin/python assets/tools/check_bgm_v2.py
.venv/bin/python assets/tools/finalize.py
```

보존 검사는 이번 작업 시작 시점의 파일 해시를 기준으로 합니다. 이후 게임 코드나 효과음을 별도 수정하면 보존 검사에서는 그 차이를 감지합니다. v2 재생성 스크립트는 `build_bgm_v2.py`이며, 기존 `build_audio.py`는 이전 버전의 음악과 효과음을 만드는 스크립트이므로 이번 재생성에는 사용하지 않았습니다.
